# Stamp Edge：能力、原理与限制分析

研究基线：上游 commit `2b89ce823aa589e912fcfbb9b529fa893142ab63`。

## 1. 它解决的真实问题

上游把一个重复但明确的视觉操作封装为 Agent 可调用能力：用户不必记住 Pillow 命令，只需说“做成邮票边”，Agent 根据 `SKILL.md` 找到输入、选择 `margin` / `bg` 选项、执行脚本并检查输出。

因此项目包含两层价值：

1. **视觉执行层**：确定性地产生齿孔边缘、透明画布、投影和多图合集；
2. **Agent 接口层**：定义触发词、命令、默认值、检查步骤和交付提醒。

它不进行主体识别、语义构图、生成式改画，也不调用远程 API。

## 2. 执行链路

```text
用户自然语言
  -> SKILL.md 命中“邮票边 / perforated edge / stamp sheet”等触发词
  -> Agent 定位图片并选择 default / margin / bg
  -> stamp_effect.py 创建邮票 PNG
  -> 可选：stamp_sheet.py 把多张 PNG 排为合集
  -> Agent 读回成品并返回路径
```

`SKILL.md` 是操作协议，不负责像素计算；像素结果完全由 Pillow 脚本决定。

## 3. `stamp_effect.py` 如何工作

### 3.1 邮票轮廓

脚本先创建全白的灰度蒙版，然后在矩形四条边绘制黑色圆。圆心落在边界上，因此最终只切入半个圆，形成连续齿孔。

关键参数：

| 参数 | 固定值 | 作用 |
| --- | ---: | --- |
| `hole_r` | 14 px | 齿孔半径 |
| `pitch` | 46 px | 齿孔中心间距 |
| `margin` | 0 / 46 px | 图片与邮票边之间的白色纸边 |
| `outer_pad` | 90 px | 输出画布的投影空间 |
| `shadow_alpha` | 70 / 255 | 阴影强度 |

齿孔数量由当前宽高和 `pitch` 计算，起点重新居中，因此不同尺寸图片的末端不会简单截断固定序列。

### 3.2 透明输出和投影

邮票本体应用齿孔蒙版；同一蒙版经过高斯模糊、偏移和第二次模糊后形成软阴影。默认画布是 RGBA 全透明，`bg` 选项则使用浅灰白背景并在保存前转换为 RGB。

本地验证结果：

- 默认结果为 `RGBA`，Alpha 范围包含 `0..255`；
- `bg` 结果为 `RGB`，不含透明通道；
- `margin` 会使邮票本体宽高各增加 92 px，整个输出也相应增大；
- 投影仍位于透明画布内，所以透明输出的外接尺寸大于邮票本体。

### 3.3 已验证的 Alpha 限制

脚本在贴入原图后调用 `stamp.putalpha(mask)`，这会用邮票外形蒙版替换整个 Alpha 通道，而不是与输入图片原 Alpha 相乘。

本地实验使用一张中心完全透明的 RGBA 输入：

- 输入中心 Alpha：`0`；
- 处理后对应中心 Alpha：`255`。

因此“输出四周和齿孔真透明”是成立的，但“保留输入图片内部原有透明区域”并不成立。若要支持透明素材，应该使用 `ImageChops.multiply(input_alpha, mask)` 或等价组合。

## 4. `stamp_sheet.py` 如何工作

合集脚本做四件事：

1. 按列宽等比缩放所有 RGBA 图片；
2. 按高度从大到小排序；
3. 每次把下一张图片放进当前最矮的列；
4. 使用图片自身 Alpha 合成到指定底色的 RGB 画布。

这是经典的“最长项优先 + 最短列”贪心排布。它能快速平衡列高，但会改变用户传入顺序；上游文档已明确这是预期行为。

## 5. 新版场景与效果矩阵

为了避免抽象测试卡片低估上游效果，本地第二轮复现改用更接近真实交付的内容：

| 场景 | 输入来源 | 画幅 | 验证重点 |
| --- | --- | --- | --- |
| 海岸旅行 | OpenAI 内置 ImageGen 原创摄影 | 横向 3:2 | 风景收藏感、默认透明、白边与底色对照 |
| 雨中建筑 | OpenAI 内置 ImageGen 原创摄影 | 竖向 4:5 | 规则几何与齿孔边缘关系 |
| 早餐静物 | OpenAI 内置 ImageGen 原创摄影 | 方形 1:1 | 细节密集图片缩小时的可读性 |
| 植物温室 | OpenAI 内置 ImageGen 原创摄影 | 横向 4:3 | 复杂纹理与透明投影 |
| 旅行社交长帖 | 本地 Pillow 确定性组装 | 竖向长图 | 复现上游示例所代表的截图场景 |
| 建筑编辑海报 | 本地 Pillow 确定性组装 | 竖向 3:4 | 已有完整排版的内容卡处理 |

所有图片的邮票边仍由未修改的 `stamp_effect.py` 生成。摄影素材提示词记录在
`demo/PROMPTS.md`，场景来源和输出模式记录在
`showcase/assets/demo/manifest.json`。

合集同时复现上游 README 中的两种主要调用：

- 默认 4 列深色背景：`collection-dark-4col.png`；
- 自定义 3 列纸色背景：`collection-paper-3col.png`。

这组实验表明：该工具最适合处理本身已有较高信息密度或完整内容层级的图片。齿孔与投影负责增加媒介感，不能替代输入图片自身的视觉质量。

## 6. 本地扩展实现（非上游能力）

研究仓库已经把扩展路线中的第一批效果实现为独立
`extension/image-style-skill/`，并保持上游 submodule 不变。

六个 preset 共用 `scripts/style_effects.py`：

- `polaroid`：暖白纸框、加厚底边与可选题注；
- `torn-paper`：带固定 seed 的不规则撕纸蒙版；
- `film-frame`：黑色片框、上下透明齿孔和帧号；
- `ticket`：横向裁切、票根信息区、侧边缺口；
- `riso-print`：蓝红双色、边缘错版、网点与纸色底；
- `sticker-outline`：对输入 Alpha 做形态膨胀，生成白色轮廓与阴影。

这些效果均为离线、确定性的 Pillow 处理。`sticker-outline` 只处理已有 Alpha，
不包含主体识别或自动抠图。六种输出和混合合集位于
`showcase/assets/extensions/`，行为测试位于
`extension/image-style-skill/tests/test_presets.py`。

## 7. 工程质量评估

| 维度 | 评价 | 依据 |
| --- | --- | --- |
| 可理解性 | 高 | 两个脚本合计规模很小，数据流直接 |
| 确定性 | 高 | 无网络、无模型、无随机参数 |
| 依赖风险 | 低 | 只有 Pillow |
| CLI 完整度 | 中低 | 合集脚本使用 `argparse`，单图脚本直接读取 `sys.argv` |
| 尺寸适配 | 低 | 孔径、孔距、边距、阴影均为固定像素 |
| 图像保真 | 中 | JPEG/普通 RGB 输入表现稳定；原始 Alpha 不保留 |
| 抗锯齿 | 中低 | 齿孔蒙版按输出分辨率直接绘制，没有超采样 |
| 自动化测试 | 无 | 上游固定版本未提供 tests |
| 发布成熟度 | 低 | 无包结构、release、CI 和许可证文件 |
| 安全性 | 较好 | 仅本地读写指定图片；无 `eval`、Shell 拼接、网络或密钥 |

## 8. 最适合与不适合的场景

适合：

- 社媒截图、照片、作品卡片的快速装饰；
- 透明贴纸素材和复古主题拼贴；
- 多图合集或 moodboard；
- 教学 Agent Skill 的最小闭环；
- 对确定性、离线执行和低成本有要求的批前处理。

不适合：

- 沿人物或商品主体轮廓自动生成贴纸；
- 自动抠图、内容感知构图和生成式风格迁移；
- 需要印刷规格、色彩管理或矢量输出的专业生产；
- 图片尺寸跨度极大但不允许手动调参的批处理；
- 在未澄清上游许可证前直接商用或再分发。

## 9. 研究判断

值得研究的不是齿孔算法本身，而是它展示的能力封装方式：**让 Agent 负责理解意图，让小型确定性程序负责稳定地产出文件**。算法阅读成本很低，适合作为进一步构建模块化图片风格 Skill 的起点。
