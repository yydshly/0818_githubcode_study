# 从邮票边扩展为通用图片风格系统

> 实现状态（2026-08-19）：Phase 1 的六个高频 preset 已在
> `extension/image-style-skill/` 落地并通过行为测试；Phase 0 中针对原上游脚本的
> 参数化与 Alpha 修复仍保持为后续工作，避免混淆上游与本地扩展。

## 目标

把当前单一的“邮票效果”演进为 `image-style-skill`：输入图片与一个预设，组合形状、边框、材质、色彩、投影和排版模块，输出透明素材或成品图。

扩展原则：保留当前项目“离线、确定性、可读、可复现”的优势；只有内容感知任务才引入 AI。

## 一、效果地图

| 家族 | 可扩展效果 | 仅 Pillow 可做 | 需要额外能力 |
| --- | --- | --- | --- |
| 边缘 | 邮票、波浪、锯齿票券、圆角、胶片齿孔 | 是 | 主体轮廓贴纸需要分割 |
| 纸张 | 撕纸、拍立得、明信片、旧纸、折痕 | 大部分 | 真实材质需要纹理资产 |
| 印刷 | 半色调、双色调、蓝晒、丝网、Riso、复印机 | 是 | 高保真色彩管理需专业库 |
| 影像 | 黑白、褪色、胶片颗粒、漏光、VHS、像素化 | 是 | 生成式改画需要图像模型 |
| 模板 | 票根、登机牌、收藏卡、封面、金句卡 | 是 | 自动文案可接 LLM |
| 布局 | 网格、瀑布流、照片墙、散落拼贴 | 是 | 内容感知排序可接视觉模型 |

## 二、推荐架构

```text
用户请求
  -> Agent 路由：选择 preset，提取可调参数
  -> 输入规范化：方向、尺寸、色彩模式、Alpha
  -> Shape：轮廓与裁剪蒙版
  -> Border：白边、色边、齿孔、胶片孔
  -> Material：纸纹、噪点、磨损、折痕
  -> Color：复古、双色、网点、胶片
  -> Depth：投影、压纹、胶带
  -> Layout：单图、网格、瀑布流、自由拼贴
  -> Output：透明 PNG / JPG / WebP + 元数据
```

目录建议：

```text
image-style-skill/
├── SKILL.md
├── cli.py
├── engine/
│   ├── masks.py
│   ├── borders.py
│   ├── materials.py
│   ├── color.py
│   ├── depth.py
│   └── layouts.py
├── presets/
│   ├── stamp.json
│   ├── polaroid.json
│   ├── torn-paper.json
│   ├── film-frame.json
│   ├── ticket.json
│   └── vintage-card.json
├── textures/
└── tests/
```

预设示例：

```json
{
  "name": "stamp",
  "shape": {"type": "perforated", "radius_ratio": 0.018, "gap_ratio": 0.024},
  "border": {"width_ratio": 0.055, "color": "#fffdf7"},
  "material": {"texture": "paper-subtle", "opacity": 0.12},
  "depth": {"shadow_blur_ratio": 0.018, "offset": [0.006, 0.012], "opacity": 0.27},
  "output": {"format": "PNG", "background": "transparent"}
}
```

使用相对比例代替固定像素，是从“脚本”走向“引擎”的第一项关键改造。

## 三、建议分阶段实施

### Phase 0：加固现有邮票能力

- 为 `stamp_effect.py` 增加 `argparse`；
- 参数化孔径、孔距、边距、阴影和背景；
- 使用尺寸比例与安全上下限；
- 保留输入 Alpha；
- 2x/4x 超采样绘制蒙版后降采样；
- 增加批处理、错误提示、测试和明确许可证。

验收：RGB、RGBA、横图、竖图、小图和超大图均能稳定输出；透明输入往返不丢 Alpha。

### Phase 1：六个高频确定性预设（已完成）

优先顺序：

1. 邮票 `stamp`
2. 拍立得 `polaroid`
3. 撕纸 `torn-paper`
4. 胶片 `film-frame`
5. 复古票券 `ticket`
6. 轮廓贴纸 `sticker-outline`（先支持已有 Alpha 的输入）

这些预设共享蒙版、边框、纹理、投影和排版模块，能覆盖社媒、报告配图、照片整理和数字素材场景。

当前实现名称为 `polaroid`、`torn-paper`、`film-frame`、`ticket`、
`riso-print`、`sticker-outline`。统一 CLI、Skill 协议、生成脚本、测试和实际输出均已归档。

### Phase 2：模板与批量生产

- 标题、日期、编号、角标和二维码区域；
- 主题 token、字体回退和安全区域；
- 预览图与生产图两级输出；
- JSON manifest 记录输入、预设、参数、版本和输出；
- 网格、瀑布流、照片墙与自由拼贴；
- 并行处理、缓存和失败重试。

验收：同一 manifest 可以完全复现相同输出；合集保持可指定顺序或明确选择“视觉均衡排序”。

### Phase 3：可选 AI 增强

只在确定性算法无法解决时引入：

- 主体分割与自动抠图；
- 沿主体轮廓生成贴纸白边；
- 内容感知裁切和安全区域；
- 根据画面语义推荐模板；
- 生成纹理或装饰素材。

AI 输出必须进入确定性后处理和质量检查，不应替换基础引擎。

## 四、Skill 层的路由设计

Agent 需要区分四类意图：

| 用户表达 | 路由 |
| --- | --- |
| “做成邮票/拍立得/胶片” | 选择明确 preset |
| “做得复古一点” | 给出 2–3 个可解释预设，不直接随机处理 |
| “沿人物边缘做贴纸” | 检查是否已有 Alpha；否则进入分割能力 |
| “把这些图片排成合集” | 询问或推断顺序优先 / 视觉均衡优先 |

每次交付应返回：预设名、关键参数、输出路径、是否透明、是否改变顺序，以及需要注意的平台压缩问题。

## 五、测试矩阵

最低测试集：

- 输入：RGB、RGBA、灰度、横图、竖图、1:1、小于孔距的极小图片；
- 输出：透明 PNG、实色 PNG、JPG/WebP（如支持）；
- 视觉合同：边缘闭合、角落无破洞、阴影不裁切、原 Alpha 保留；
- 参数合同：比例参数跨尺寸表现一致，非法颜色/列数给出明确错误；
- 布局合同：顺序模式不改序，均衡模式可记录最终序列；
- 性能：典型 2000×2000 输入的耗时与峰值内存有基线。

## 最终判断

最有价值的扩展不是堆积几十个独立脚本，而是形成一个小型、模块化、预设驱动的确定性渲染引擎。邮票只是第一个 preset；Agent Skill 则负责把用户语言稳定映射到这些可测试的 preset 和参数。
