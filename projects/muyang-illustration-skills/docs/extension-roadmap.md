# Muyang Illustration Skills 后期研究与扩展路线

当前阶段已固定并安装上游能力，并以统一主体完成 8 个分类各 1 张的基础样例；没有修改配方，也没有展开到 25 风格全覆盖或重复采样。下面内容是后续研究路线，不是当前实现承诺。

## 总原则

先建立证据，再扩展能力：优先回答“现有配方是否稳定、适合什么主体、在哪些模型上有效”，之后再决定是否增加新风格、图生图或生产系统。

## 阶段 1：建立可复现基线

目标：把当前“8 类各 1 张”的基础横向样例升级为可复现、可评分的实验资产。

- 固定图像模型名称与版本；
- 记录生成日期、尺寸、质量参数和完整调用元数据；
- 为每个风格选定统一的三类主体：人物、动物、场景；
- 每个组合重复生成至少 3 次；
- 保留成功、失败与边缘案例，不只保留最好结果；
- 将本阶段观察到的“纯白高定自动生成版面文字”等偏差纳入失败类型；
- 建立人工评分表：风格符合度、主体符合度、构图可用性、瑕疵率。

完成标志不是“图片更多”，而是能回答每个风格的稳定性和适用范围。

## 阶段 2：配方兼容性与质量门禁

目标：识别固定配方的主体偏置与模型耦合。

- 建立风格 × 主体类型 × 模型版本兼容矩阵；
- 自动检查主体与配方的明显语义冲突；
- 为人物导向、场景导向和通用型配方增加结构标签；
- 对长 Prompt 做消融实验，找出真正影响风格的关键描述；
- 版本化配方，并保存变更前后的回归结果；
- 定义 fail-closed 条件：缺风格、未知风格、资产缺失时停止而不是猜测。

这一阶段可以改进工程可靠性，但不应悄悄改变上游固定配方；实验变体要放在独立命名空间。

## 阶段 3：参考图与图生图

目标：支持“输入一张图，在保留关键内容的前提下转为某种插画风格”。

需要新增明确的输入合同：

| 字段 | 示例 | 作用 |
| --- | --- | --- |
| 参考图片 | 用户上传照片 | 提供身份、构图、姿态或产品结构 |
| 保留项 | 人脸、服装颜色、镜头位置 | 防止风格化时丢失核心信息 |
| 可改变项 | 材质、色板、背景简化 | 指定风格化空间 |
| 风格 | 庭院手绘插画 | 选择固定视觉方向 |
| 强度 | 低 / 中 / 高 | 控制原图与风格之间的权重 |

同时需要真实图像编辑工具调用、身份一致性检查、隐私说明和失败回退。仅在 Prompt 中写“参考这张图”并不能形成可靠图生图能力。

## 阶段 4：产品化与团队协作

目标：让配方库可维护、可审计、可批量使用。

- 风格选择器与标签搜索；
- 调用记录、模型成本和生成元数据；
- 团队级配方版本、审批和回滚；
- 品牌色、禁用元素和版权规则；
- 批量任务、队列、失败重试和结果审核；
- 输出资产的来源、许可证、Prompt 版本和模型版本清单；
- 针对封面、社媒、PPT 和出版物的尺寸预设。

其中“文字产品化”必须作为独立确定性层实现，而不是要求图片模型直接写字：

```text
无字插画底图
  + 标题 / 副标题 / 品牌 / 日期 / CTA
  + 尺寸与排版模板
        ↓
HTML / SVG / Canvas 确定性排版
        ↓
准确性 / 安全区 / 对比度 / 溢出检查
        ↓
PNG / PDF / Web 成品
```

图生图与文字排版解决不同问题：前者控制人物、姿态、构图或产品结构的一致性；后者保证最终文字内容准确、可编辑和可复用。两者应在产品管线中组合，但不能互相替代。

## 值得优先研究的三个问题

1. **固定配方真的比 Agent 自由改写更稳定吗？** 需要同主体、同模型、同采样次数的 A/B 对照。
2. **25 个风格是否彼此可区分？** 可以用盲评和图像嵌入聚类检查风格间距。
3. **哪些配方只适用于人物？** 通过人物、动物、产品、建筑和纯场景的分层测试建立适配标签。

## 暂不建议的扩展

- 在没有基线前继续大量增加相似风格；
- 将上游示意图默认用作商用参考资产；
- 把 Prompt 隐藏当作知识产权或安全机制；
- 未记录模型版本就宣称“稳定复现”；
- 同时混入多套风格，导致无法判断哪一部分有效。

## 重新进入开发的触发条件

满足下列任一条件后，可以开启下一轮实施：

- 用户明确要求从 8 类基础样例扩展到重复采样、更多主体或 25 风格全覆盖；
- 已确定要支持的模型和生成预算；
- 已准备可合法使用的统一测试主体；
- 已明确图生图中的保留项和隐私边界；
- 现有 25 种风格出现可复现的具体失败，需要修订配方或流程。
