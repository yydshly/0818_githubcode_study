# Muyang Illustration Skills：能力、原理与边界

## 1. 它解决什么问题

普通用户常常知道“想画什么”，却不擅长把构图、色板、材质、光影和负面约束组织成稳定的生图 Prompt。Muyang Illustration Skills 把这部分经验预先整理为 25 套固定配方，再用 Codex Skill 约束 Agent 的交互和调用方式。

它主要解决三个问题：

1. **选择成本**：把风格收敛成 8 类、25 个有名称的选项。
2. **Prompt 编写成本**：用户只需要提供主体文字，不需要自己写完整 Prompt。
3. **Agent 漂移**：明确禁止润色主体、补故事、混合配方或向用户展示内部 Prompt。

它没有改变底层图像模型的能力上限。最终画质、文字准确性、人物一致性和指令遵循仍取决于宿主调用的图像生成模型。

## 2. 输入与输出

### 必填输入

| 输入 | 类型 | 规则 |
| --- | --- | --- |
| 主体 | 文字 | 必须由用户亲自提供；可短可长，但 Agent 不得擅自扩写 |
| 具体风格 | 枚举文字 | 必须是 25 个固定名称之一；缺失时只能询问或推荐，不能自动替用户决定后出图 |

### 可选输入

- 画幅，例如 `9:16`；
- 用户明确提出的硬限制，例如“不要出现文字”。

这些可选限制按上游规则原样追加在固定配方末尾，不重写配方正文。

### 输出

在真实 Codex 任务中，Skill 将完整内部配方交给可用的图像生成工具，并直接返回生成图片。它不应该向用户显示或总结内部 Prompt。

仓库内的 `assets/` 是风格示意图。现有 Skill 文档只要求读取它们“核对对应风格”，没有要求把这些图片作为参考图输入图像模型，因此现状仍属于**文字驱动的文生图**。

## 3. 五层工作原理

```text
用户请求层
  主体文字 + 具体风格 + 可选硬限制
        ↓
总入口路由层
  muyang-illustration 将风格名映射到 8 个子 Skill 之一
        ↓
固定配方层
  子 Skill 读取 references/recipes.md，只替换【主体内容】
        ↓
宿主工具层
  Codex 调用当前可用的图像生成工具
        ↓
模型输出层
  外部图像模型生成并返回图片
```

### 总入口

`muyang-illustration/SKILL.md` 保存 25 个风格名到 8 个兄弟 Skill 的路由表，并负责检查主体和风格是否齐全。

### 子 Skill

每个子 Skill 的结构相同：

```text
skill-name/
├── SKILL.md                 # 输入校验、填槽和输出限制
├── agents/openai.yaml       # Codex 显示名、简述和默认调用提示
├── references/recipes.md    # 2–5 个固定 Prompt 配方
└── assets/*.png             # 对应风格示意图
```

### 固定填槽

上游最重要的行为不是“让 Agent 优化 Prompt”，而是限制 Agent：复制同名配方全文，只替换 `【主体内容】`，并保持配色、构图、材质、光影和负面约束不变。

这是一种低自由度模板系统。优点是可预期，缺点是主体与配方假设冲突时也不能自适应修复。

## 5. 适合的使用场景

- 公众号、博客、播客和视频封面；
- 小红书、社交媒体和活动视觉；
- 小说、诗歌、音乐歌单的概念配图；
- 提案、研究报告和 PPT 的气氛图；
- 同一栏目需要重复调用近似视觉语言；
- 团队希望把个人 Prompt 经验变成可安装的共享入口。

这些场景共同特点是：允许模型保留一定生成自由，对像素级复现和主体身份一致性要求不高。

## 6. 当前限制与风险

### 6.1 不是图生图

用户不能仅靠现有 Skill 输入一张照片并要求保持人物身份、姿态和构图。要实现这种能力，工具调用必须显式携带参考图片并定义保留/改变规则。

### 6.2 固定配方存在主体偏置

不少配方隐含“人物、时装、修长比例、安静姿态”等假设。将汽车、建筑、动物或抽象概念填进去时，语义可能冲突。由于 Skill 又禁止改写配方，Agent 无权自动消除冲突。

### 6.3 已有第一版横向对照，但还没有稳定性证据

本研究新增了统一主体“一个女孩在窗边读书”的 8 张样例，每个分类选择一个代表风格。它们能够直观看到同一主体经过不同固定配方后的构图、色彩和材质差异，但每种只有一个入选结果，仍缺少重复采样、模型版本、Seed、成功率和人工评分，因此无法回答“同一风格重复生成是否稳定”。

“柔纱纯白插画”在两次尝试中都出现了模型自行添加的杂志版面文字。这是有价值的负面结果：配方中的“时装杂志封面感”会触发底层模型的文字联想，说明固定模板能约束方向，却不能保证所有细节都被遵循。

### 6.4 “隐藏 Prompt”不是安全边界

Skill 要求交互过程中不显示内部 Prompt，是产品体验约束，不是秘密保护机制。配方本身存在于公开仓库中。

### 6.5 模型耦合未管理

同一中文 Prompt 在不同图像模型、模型版本和内容政策下可能产生明显不同结果。上游没有兼容矩阵和版本锁定。

### 6.6 素材授权需要单独处理

上游说明 Skill 指令、Prompt 整理和文档采用 MIT License，但 25 张示意图不包含在 MIT 授权范围内。研究展示应保留来源说明；重新分发、商用或制作衍生作品前需要确认图片权利。

### 6.7 人物一致性需要参考图与保留合同

当前文字输入只能控制“一个女孩在窗边读书”这类语义，无法稳定锁定同一张脸、发型、服装、姿态和镜头。强控制模式需要新增参考图片、必须保留项、允许改变项与风格化强度，并把图片真正传给支持编辑的图像工具。只修改 Skill 文案或在 Prompt 中增加“保持一致”不能形成可靠的图生图能力。

建议把一致性流程拆为：参考图 → 保留合同 → 图像编辑 → 身份/姿态/结构检查 → 不合格重试或人工确认。

### 6.8 文字产品化应与插画生成分层

封面、海报、社媒卡和报告视觉通常需要准确的标题、副标题、品牌、日期或行动按钮。模型在图片中随机生成的文字可能错误、乱码或不可编辑，即使视觉上像杂志，也不能作为稳定产品能力。

更可靠的架构是先生成无字插画底图，再由 HTML、SVG、Canvas 或设计模板进行确定性排版，最后检查文字准确性、安全区、对比度和溢出。图片模型负责艺术层，排版系统负责内容层。

## 7. 研究价值判断

| 研究方向 | 价值 | 原因 |
| --- | --- | --- |
| Codex Skill 结构 | 中等偏高 | 展示总入口、子技能、配方和资产如何组织成可安装能力 |
| Prompt 产品化 | 中等偏高 | 把审美经验从文本片段变成枚举、校验和固定填槽流程 |
| Agent 约束设计 | 中等 | 用禁止扩写、禁止混配和缺项询问控制代理自由度 |
| 图像算法研究 | 低 | 没有模型、训练、推理或图像处理实现 |
| 可复现生成研究 | 当前较低 | 缺少参数、批量样本、对照和评分；需要后续实验补齐 |

## 8. 本研究的真实性边界

- 展厅主展示区是**本研究生成的 8 张统一主体样例**，文件保存在 `showcase/assets/generated/`。
- 上游原样例区是**上游已有的 25 张示意图**，在网页中直接完整展示，并明确标为“上游示意”。
- 工作台展示的是**合法用户调用文本**，不是内部完整 Prompt，也不会触发模型。
- 图生图一致性与确定性文字排版在网页中属于**后期产品架构说明**，当前尚未实现编辑引擎或排版引擎。
- 页面中的未来能力均标为路线，不代表已经实现。
- 8 个分类各生成一张只证明基础调用有效且风格差异可见，不自动证明 25 种风格在每个模型上都稳定。
