# Punk IP Illustrations：能力、原理与真实边界

## 一句话定位

这是一个“固定角色身份，再让同一角色持续进入不同文章场景”的 Agent Skill。仓库不训练或托管图像模型，而是提供阶段路由、人物参考合同、文章插图规则、角色注册脚本和本地资产结构。

研究固定版本：`8bcc522192a9f757cbf2b52cefabc9ffbfb1712c`。

## 三层能力边界

### 上游仓库真正提供

- 从首次引导、创建、修订、确认到文章配图的阶段路由。
- 角色设定板、干净人物参考图和 `character-spec.md` 的生成合同。
- `draft` 与 `confirmed` 状态，以及当前角色选择规则。
- 文章图片数量、认知锚点、表现模式、文件命名和插入位置规则。
- 无外部依赖的 `character_registry.py`，负责注册、确认、激活、解析和列出角色。
- 复古彩色扁平 3D 小剧场这一套固定视觉语言。

### 宿主 Agent 与图像工具负责

- 读取照片并提炼视觉身份。
- 从完整文章中选择真正值得可视化的观点。
- 组装每张图的提示并调用图像生成/编辑接口。
- 生成最终像素、理解参考图并保持角色一致。
- 判断生成结果是否语义正确、人物漂移或文字错误。

### 用户必须负责

- 提供有权使用的人物照片和角色名。
- 在角色阶段明确确认或提出修改。
- 判断肖像是否足够相似、是否可用于公开内容。
- 决定是否允许修改原 Markdown，以及最终发布位置。

## 为什么它比普通“参考图生图”多一步

普通调用往往只有“给照片 + 写提示 + 出图”。该 Skill 增加了持续使用所需的状态和资产：

1. 原始人物照片只作为身份来源。
2. 生成角色设定板与干净参考图。
3. 将稳定外观写入人物规范。
4. 以草稿角色注册，不能直接用于文章。
5. 用户明确确认后，状态变为 `confirmed` 并成为当前角色。
6. 后续文章只解析已确认角色，并默认使用干净参考图。

这形成一个小型的人在回路状态机。它不能从算法上消除身份漂移，但能减少“每次重新描述人物”和“错误版本进入生产”的概率。

## 两种文章表达模式

### 流程拆解

适合步骤、方法、教程和工作流。文章内容被压缩为 3—5 个节点，同一角色可以在不同节点重复出现，但每个分身需要承担不同动作。它强调阅读顺序与输入到输出的变化。

### 核心动作

适合观点、冲突、处境和反直觉判断。每张图只保留一个人物、一个核心物件或紧凑物件组、一个动作和一个可见结果。它强调“一个物理关系承载一个判断”。

两种模式都被限制为 16:9、纯白页面、大面积留白、低细节和有限色彩。它不是通用风格库。

## 确定性实现审计

`scripts/character_registry.py` 是仓库唯一主要程序文件，使用 Python 标准库完成：

- slug 格式校验；
- 资产复制与 `-v2`、`-v3` 非覆盖版本；
- manifest 原子写入；
- 角色状态确认与当前角色指针；
- 资产存在性检查；
- 列表、激活和绝对路径解析。

它没有图像处理、视觉相似度计算、文章分段算法、模型 API 客户端、队列或数据库。因此“自动决定配图数量”和“角色一致”主要是 Agent 按文档协议执行，并非脚本算法保证。

## 主要价值

- **重复使用：** 将一次人物设定转成可跨文章调用的资产包。
- **生产门禁：** 草稿角色不能被激活，用户确认成为唯一强制暂停点。
- **上下文节省：** 后续调用不需要重新上传和描述整个人物。
- **内容适配：** 不是逐段配图，而是选择总判断、机制、转折、冲突和行动结论。
- **交付可追踪：** 报告图片路径、用途和插入位置，并避免覆盖旧版本。

## 实际使用：把内容与角色在生成时绑定

原始人物图与文章场景不是直接关联的。第一次使用时，原始图只用于建立并确认角色资产；后续生产时，用户再提交一句意图、文章大纲或完整文章。Agent 负责从内容中选择认知锚点，Skill 约束模式、角色状态、画面合同和文件交付，图像模型同时读取确认角色参考与场景计划生成最终图片。

| 内容输入 | 适合阶段 | 规划特征 | 典型输出 |
| --- | --- | --- | --- |
| 一句意图 | 方向探索 | AI 需要补足大部分结构，结果较概括 | 1—2 张概念图或初步计划 |
| 文章大纲 | 写作中期 | 能按章节规划，但缺少完整论据和转折 | 3—5 张章节配图计划 |
| 完整文章 | 正式生产 | 可识别总判断、机制、冲突、转折和行动结论 | 1—8 张配图、理由与插入位置 |

没有可用图像生成工具时，这条工作流仍可交付图片计划、提示与插入位置，但不能产生最终 PNG。

## 真实限制

- 角色一致性不是数学保证，仍受图像模型参考图能力影响。
- 四视图本身可能出现身份、服装或左右配件漂移。
- 文章认知锚点由 LLM 判断，缺少可重复的结构化评分。
- 图片内中文仍可能错误；仓库策略是减少文字并重试。
- 风格较窄，不适合写实摄影、复杂数据图、封面海报或多品牌视觉系统。
- 没有自动化测试、评估集、正式 release 或生产监控。
- 角色源资产使用单独许可证，不等同于 MIT 工作流许可。

## 本研究自有实演

为了避免把上游样张当作自己的能力复现，本研究另外构造“研究一个开源项目并发布 Web 结论”场景，并使用 ImageGen 生成的虚构人物“小岚”作为模拟原始图。实际链路包含四类可复核资产：

1. `xiaolan-source.png`：虚构、照片式的身份输入，不涉及真人肖像。
2. `xiaolan-character-sheet.png`：将单一正面输入扩展成主视图与四向设定。
3. `xiaolan-character-reference-clean.png`：人工检查后作为 `confirmed` 身份参考。
4. `xiaolan-open-source-research-workflow.png`：同一角色依次完成收集仓库、阅读 Skill/脚本、验证证据和发布 Web 结论。

本轮观察到蓝色挑染、圆框眼镜、芥末黄外套、海军蓝长裤、白鞋和珊瑚红挎包在四个动作中均保持可辨识；变化集中在姿态、视线和研究道具。这支持“角色身份固定、内容语义变化”的工作流假设，但单次成功样张不能证明算法级一致性，仍需跨角色、跨模型和多轮重复实验。

完整资产与生成记录见 [`showcase/assets/generated/`](../showcase/assets/generated/)。原有上游公开样张继续保留在展厅的独立证据区。

## 研究价值判断

| 方向 | 判断 | 原因 |
| --- | --- | --- |
| Agent Skill 结构 | 中高 | 阶段路由、渐进读取和失败降级较完整 |
| 人在回路设计 | 中高 | 将人工确认放在成本与风险最高的身份定稿点 |
| 本地状态与记忆 | 中高 | 小型角色包足以研究跨任务身份复用 |
| 长文到视觉规划 | 中高 | 认知锚点与两种模式是可实验的语义规划框架 |
| 图像算法创新 | 低 | 没有训练、推理或一致性算法 |
| 生产系统成熟度 | 中低 | 缺少评估、观测、并发、权限与团队审核能力 |
