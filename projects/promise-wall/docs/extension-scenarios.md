# Promise Wall 使用场景与扩展路线

## 场景路由原则

Promise Wall 的通用结构不是“承诺”，而是：

```text
短内容 + 视觉身份 + 空间位置 + 查看详情 + 轻量互动
```

只要业务对象符合这个结构，就可以复用其表达方式。

## 直接使用场景

| 场景 | 替换的数据 | 保留的交互 | 必要补充 |
| --- | --- | --- | --- |
| 校园／公益心愿墙 | 心愿、署名、班级／活动 | 张贴、浏览、分类 | 审核、匿名与敏感词 |
| 企业文化或团队目标墙 | 目标、负责人、团队、周期 | 搜索、聚焦、收藏 | SSO、权限、状态同步 |
| 展会／婚礼／毕业季留言墙 | 祝福、照片、来宾 | 放置、照片卡、最近添加 | 二维码入口、上传、投屏模式 |
| 品牌故事与用户证言 | 故事、人物、主题、产品 | 空间浏览、详情、筛选 | CMS、编辑审核、分析埋点 |
| 私人反思与习惯墙 | 目标、日期、复盘、进度 | 创建、查看、反思 | 本地优先存储、隐私和导出 |
| 游戏任务／线索墙 | 任务、线索、人物、关系 | 拾取、聚焦、空间探索 | 任务状态、连线、存档 |
| 研究灵感墙 | 论文、观点、来源、标签 | 搜索、分类、详情 | 引用、附件、全文索引 |
| 纪念与社区故事墙 | 人物、时间、照片、故事 | 浏览、收藏、反思 | 长期存储、内容治理、无障碍 |

## 可扩展场景

### 1. 真实多人社区

增加身份认证、数据库、实时订阅、乐观更新、分页、举报队列和审核后台。这里必须重新定义状态所有权，不能继续直接修改 `p.support` 这样的内存对象。

### 2. 可分享空间

把相机位置、过滤器、卡片坐标和选中对象序列化为版本化 JSON；支持本地保存、JSON 导入导出和带 ID 的分享链接。公开分享需要后端，不等同于 Local Storage。

### 3. 关系图／调查板

给卡片增加语义端口与连线，用曲线、颜色和分组表达因果、人物或证据关系。需要碰撞避让、连线拾取、自动布局和更严格的可读性控制。

### 4. 时间与进度

将“墙”扩展为过去、现在、未来或季度时间轴；卡片状态驱动材质、位置和聚类。适合 OKR、习惯、项目里程碑和故事档案。

### 5. 多媒体卡片

支持真实图片、音频、短视频、PDF 缩略图和 3D 模型。必须增加上传、转码、尺寸预算、懒加载、占位图和媒体权限处理。

### 6. AI 辅助组织

AI 可以建议分类、标签、相似卡片聚类、摘要和反思问题，但不应自动公开内容或替代审核。模型能力是外部扩展，不属于上游已有能力。

### 7. 展厅与自动导览

将相机路径、卡片聚焦和字幕编排成自动播放路线，适合活动开场、品牌故事和研究演示。需要确定性导演时间线、暂停／重播和 reduced-motion 替代。

### 8. 千级卡片引擎

面向数百到数千卡片时，引入分页／分块、纹理图集、可见性裁剪、对象池、简化阴影和质量档位。先建立 20／100／500／1000 张卡片的 CPU、GPU、显存和交互基线。

## 推荐产品化路线

### Phase 0：工程整理

- 将 3587 行入口拆分为 data、textures、scene、cards、interaction、ui；
- 将 Three.js 和 GSAP 纳入 npm 依赖；
- 删除或替换失效的 Vite 默认 `src/`；
- 增加类型、单元测试和最小端到端测试；
- 明确许可证后再复用源码。

### Phase 1：可信单机版

- 本地持久化与 schema 迁移；
- 导入／导出 JSON；
- 内容删除、编辑、撤销和资源释放；
- WebGL 失败时提供列表视图。

### Phase 2：真实在线产品

- 认证、数据库、API、实时同步；
- 内容审核、限流、权限与隐私；
- 上传管线与可观测性；
- 移动端触控与弱设备质量档位。

### Phase 3：场景化扩展

- 按真实业务选择关系图、时间轴、自动导览或 AI 组织中的一条；
- 为选择的场景建立任务成功指标，而不是继续叠加视觉效果；
- 用真实内容量和真实设备验证性能。

## 当前研究边界

本子项目展示上游原版、整理能力证据和提出扩展路线，不修改上游、不实现后端，也不把规划项描述为现有能力。
