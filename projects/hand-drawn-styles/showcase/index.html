PROJECT 02 / VISUAL PROMPT ENGINEERING

不是新的生图模型，
是一套视觉风格合同。

它把“画成某种感觉”拆成可选择的风格、不可随意改写的配方、可校验的输入，以及必要时必须完成的多阶段编辑流程。

上游样图证明“能画成什么样”；我们生成的内容资产回答“为什么画、代表什么、应该放在哪里”。
01 / CONNECTED CASE

从混乱样图，
到可发布视觉系统

这不是六张风格相似的插画，而是同一个研究项目的完整过程。每一幕都由上一幕的问题触发，并产生下一幕需要的输入。

BACKGROUND / 背景

图片很多，却不像同一个项目。

团队准备发布 Hand-drawn Styles 研究，但已有图片来自不同题材和画风，只能展示能力，无法建立项目自己的视觉叙事。

MISSION / 任务

把一次研究变成可持续的视觉生产流程。

同一位研究者必须完成问题定义、风格归档、任务路由、请求组装、失败复盘和成套发布。

CONTRACT / 连续性约束

一个主角，一套色板，一条因果链。

六幕固定深蓝服装、黑色发髻、暖白纸底与蓝橙色板；图片内不写字，准确叙事由页面文本承担。

SCENE 01 / PROBLEM

先承认：这些图片彼此无关。

研究者把两张结果并排拿起：一张像水彩，一张像扁平绘本；桌上还有涂鸦、3D和抽象图。单张都能看，但放在同一项目里没有共同身份。

发生原因
每次都从一句临时 Prompt 开始，没有风格真源。
当前行动
不再挑最好看的一张，而是先比较差异并定义问题。
得到结果
问题被明确为“缺少可检索、可复用的共同视觉语言”。

因此 不能继续随机生成，下一步必须先建立风格档案。

SCENE 02 / ARCHIVE

把“感觉”整理成可以选择的档案。

散乱图片被拆成构图、线条、色板、材质和禁用项，再收进统一档案。它们不再只是收藏夹里的灵感图，而是有身份的生产资产。

发生原因
知道图片不一致，还不足以指导下一次生成。
当前行动
将风格配方、样图和使用边界归档到单一真源。
得到结果
风格从模糊形容词变成可以被 Agent 选择的编号资产。

但是 有档案不代表会选，下一步要回答“这个任务该用哪一种”。

SCENE 03 / ROUTE

不是选最喜欢的，而是选最适合任务的。

研究者拿着“研究项目封面”任务卡，在风格墙中选择一张珊瑚橙配方。内容目的成为路由条件，个人偏好不再是唯一依据。

发生原因
解释流程、建立识别和讲人物故事需要不同视觉职责。
当前行动
用“要看懂、要记住、要感受”匹配对应风格。
得到结果
任务卡和风格卡形成一对明确输入。

接下来 两张卡仍不能直接出图，还需要完整规则和确定性组装。

SCENE 04 / ASSEMBLE

把内容和风格组装成正式生成合同。

内容卡与风格卡进入不同输入槽，固定规则卡负责补齐构图、色板和禁用项，最后才交给图像模型。过程看起来像组装，而不是许愿。

发生原因
只写“画成某某风”仍会被模型自由解释。
当前行动
原样提取配方、填入变量、校验锚点并生成调用包。
得到结果
同一输入可以被重复执行，内容和视觉规则互不污染。

然而 正式流程也会失败，下一幕必须让失败变成规则的一部分。

SCENE 05 / REVIEW

不删除失败图，把它写回规则。

第一张结果过于统一，缺少目标风格的局部节奏。研究者把它和修正图并排保留，再用一张橙色证据卡把缺陷连接到更新后的规则。

发生原因
Prompt正确不等于输出一定合格，模型仍有生成惯性。
当前行动
保存失败、描述差距、增加门禁并做下一轮回归。
得到结果
失败从一次性损耗变成后续生成可复用的知识。

直到 不同用途的图片都能遵守同一视觉语言，项目才具备发布条件。

SCENE 06 / PUBLISH

最后得到的不是一张图，而是一套系统。

封面负责让人记住，流程图负责让人看懂，故事图负责让人感受，分享卡负责传播。用途不同，但主角、色板、纸面和视觉语法一致。

发生原因
研究项目需要持续更新，而不是发布后就停止。
当前行动
将成套资产与档案、规则和失败证据一起交付。
最终结果
新内容可以沿同一路由与合同继续扩展，无需重新发明画风。

闭环 图片从孤立装饰，变成有背景、有因果、可持续复用的视觉系统。

BEFORE每次临时找图、临时写 Prompt
→
AFTER背景 → 路由 → 合同 → 回归 → 成套资产

STYLE 08 · INK WASH

水墨写意：把流程变成战略隐喻

混乱纸片像风暴，档案像向上延伸的墨石路径，最终抵达一卷安静画卷。它不解释每个操作步骤，而是表达“从无序到有序”的方法论气质。

背景
面向策略、文化或知识体系主题，需要更高层次的视觉隐喻。
适合
深度文章封面、方法论报告、文化研究、演讲开场。
不适合
逐步教程、产品UI说明、需要精确标签的架构图。
推荐位置
报告封面、章节扉页、专题海报。

STYLE 09 · PIXEL WORKFLOW

复古像素：把研究过程变成可完成关卡

收集卡片、进入档案检查点、在合成台组合内容与风格、到达成套资产终点。它把抽象流程转成有进度、有反馈的任务路径。

背景

适合
新手引导、课程进度、开发者社区、社媒轮播、挑战活动。
不适合
严肃审计正文、高端品牌报告、细腻情绪故事。
推荐位置
教程头图、学习路线、进度页、活动卡片。

STYLE 13 · PAPER FOLK

北欧纸雕：把系统结构变成编辑主视觉

中央档案像一座层叠纸艺装置，卷曲纸带把输入连接到封面、流程图和故事卡。它强调“系统被精心设计和制作”，而不是技术运行细节。

背景
面向设计、创意产业或发布活动，需要高识别度的手工编辑质感。
适合

不适合

STYLE 15 · VINYL RESEARCHER

大鼻软偶：把抽象项目变成角色IP

角色一手展示风格卡，一手抱着档案盒。它不承担复杂结论，而是让项目拥有可以反复出现的“研究助手”，适合建立亲近感和记忆点。

背景
面向连续栏目、短视频或社区运营，需要稳定可识别的角色。
适合
头像、贴纸、短视频封面、帮助入口、栏目主持人。
不适合
证据图、正式研究结论、架构图和严肃数据表达。
推荐位置
频道头像、侧边助手、空状态、社媒缩略图。
不是换皮风格改变了用户如何理解同一内容

水墨让人思考，像素让人行动，纸雕让人记住，软偶让人建立关系。需要精确事实时，仍应回到HTML、SVG、真实截图和数据。

05 / HOW IT WORKS

五层实现，一层真正出图

最容易产生误解的是把它当成一个图片生成器。源码恰好证明相反：仓库负责生成之前的路由、知识和调用合同。

  1. 01
    宿主适配SKILL.md / AGENTS.md

    告诉不同 Agent 何时触发，以及完整规则放在哪里。

    指令
  2. 02
    执行协议PROTOCOL.md

    识别风格、推断占位符、处理比例、选择文本或 JSON 输出。

    路由
  3. 03
    风格知识STYLES.md

    将线条、色板、材质、构图和禁止项固化成19套完整配方。

    真源
  4. 04
    确定性渲染render_prompt.py

    原样提取模板、替换变量、校验锚点并构建调用包。

    编译
  5. 05
    外部图像模型GPT Image / Midjourney / other

    真正解释 Prompt、参考图和编辑请求并生成像素。

    出图

普通风格

Prompt 是最终交付

Agent 填充内容参数，渲染器从单一真源原样取配方。下游模型负责执行，仓库不保证跨模型像素一致。

内容 → 风格编号 → 完整 Prompt → 图像模型

3.1 稳定变体

JSON 工作流才是最终交付

固定锚点随每张请求传入；前两阶段只能算中间图，只有第二次涂抹修正后的输出才能进入 final。

基础生成
  → scribble-correction
  → scribble-chaos-correction ✓
FAIL-CLOSED

错误时停止，不偷偷降级。

  • 占位符缺失或多传：拒绝
  • 锚点像素或尺寸变化：拒绝
  • 把第二套配色、线条塞进主体：拒绝
  • 3.1 正式生产只输出纯 Prompt：拒绝
06 / WHY IT MATTERS TO US

我们的扩展，是场景路由

上游已经回答“这种风格怎么画”。我们不应该再维护一份色板和线条规则，而应回答“研究与日常内容什么时候适合用它”。

研究方法

把复杂流程讲清楚

用 1 或 4 号把研究步骤、证据分级和决策链拆成多格信息图。

推荐 01 / 04
研究结论

把长报告压成一张卡

用小豆人突出要点，或用暖色扁平绘本建立更强传播识别。

推荐 04 / 18
项目封面

建立每个研究项目的视觉记忆

二维水彩适合概念气氛，暖色扁平适合清晰、现代的项目主视觉。

推荐 11 / 18
里程碑故事

让阶段成果有人和情绪

用单一橙色焦点和大片留白，把发布、修复或失败复盘变成一个场景。

推荐 10
团队故事

连续输出统一的生活化故事卡

3.1 适合人物关系和日常事件，但正式使用必须执行锚点与三阶段合同。

推荐 3.1
+
新增日常能力，只增加“场景 → 风格”的映射。

不复制 `STYLES.md`，不追加第二套风格段落，不把业务偏好混进受控主体字段。

08 / EVIDENCE & LIMITS
证据与边界

      

      

        
源码事实
渲染器不含图像 SDK
Python 标准库只负责模板、PNG像素校验和 JSON；真正生图发生在仓库之外。
查看渲染器

        
工程事实
测试验证合同，不验证审美
自动测试能证明变量、锚点和阶段状态正确，不能证明每张生成图都好看。

实验事实
保留失败样图是一项优点
