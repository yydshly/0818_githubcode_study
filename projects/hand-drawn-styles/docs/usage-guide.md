# Hand-drawn Styles 长期使用指南

## 1. 一句话定位

`hand-drawn-styles` 不是图像模型，而是位于内容需求和图像模型之间的视觉资产编排层：它帮助 Agent 按传播任务选择风格、从单一真源提取完整配方、填充内容和比例，并在需要时构建参考图与多阶段调用合同。

```text
内容需求
→ 判断图片职责
→ 选择交付场景
→ 路由风格
→ 渲染 Prompt / JSON 合同
→ ChatGPT ImageGen 等模型出图
→ 验收、归档和复用
```

## 2. 先过决策门

### 应该使用

当图片主要用于让人：

- **理解**：步骤、方法、关系、概念；
- **记住**：项目身份、报告主题、活动主视觉；
- **感受**：人物经历、里程碑、失败复盘；
- **行动**：教程、进度、挑战、传播卡；
- **建立关系**：角色IP、栏目助手、持续内容。

### 不应该使用

当图片主要用于证明事实或要求像素级准确：

- 数据图表、财务表格；
- 系统架构、API关系和精确流程；
- 代码截图、产品UI、真实测试结果；
- 原始证据、人物身份和现场照片；
- 大量准确文字、公式、坐标和标注。

这些内容应使用 HTML、SVG、Mermaid、PowerPoint 原生图形、图表或真实截图。生成插图只能辅助理解，不能替代证据。

| 场景 | 图片职责 | 常见交付 | 推荐风格 | 不要替代 |

| PPT演示 | 建立主题、章节转场、解释方法、讲案例 | 封面、章节页、流程插图、案例三幕、结束页 | 1、4、8、9、10、11、13、18 | 数据图表、精确架构、表格 |
| 报告与文章 | 提供封面、章节隐喻和故事节奏 | 报告封面、章节扉页、文章头图、案例插图 | 6、8、10、11、13、14、17、18 | 引用、统计数字、调查证据 |
| 教程与课程 | 降低理解门槛、形成步骤和进度 | 新手引导、知识卡、学习路线、前后对比 | 1、4、9、14、18 | 需要逐字准确的操作界面 |

## 4. PPT 使用方式

PPT 是重要场景，但不要让生成图片替代整张幻灯片结构。

| PPT位置 | 图片任务 | 推荐风格 |
| --- | --- | --- |
| 封面 | 建立主题和第一印象 | 11、13、18 |
| 章节页 | 转场和情绪调整 | 8、10、13 |
| 方法页 | 解释步骤和关系 | 1、4、9 |
| 案例页 | 问题→行动→结果 | 10、17、18、3.1 |
| 愿景页 | 表达未来状态 | 11、13、16、18 |
| 角色讲解 | 贯穿多页的主持人或助手 | 15 |

建议：图像模型负责插图，标题、图表、数字、流程箭头和版式由 PowerPoint 原生元素完成。

## 5. 每个研究项目的标准视觉资产包

默认不必把19种风格全部用一遍。一个研究子项目建议交付：

| 数量 | 资产 | 作用 | 建议文件名 |
| ---: | --- | --- | --- |
| 1 | 项目封面 | README、网站首屏、OG图 | `cover.png` |
| 1 | 原理讲解图 | 解释核心工作链路 | `how-it-works.png` |
| 3 | 场景流程 | 问题、处理、结果 | `case-01.png`～`case-03.png` |
| 1 | 研究结论卡 | 分享最重要结论 | `key-finding.png` |
| 1 | 社交分享图 | 视频/文章/社媒缩略图 | `social-card.png` |
| 0–1 | 项目角色 | 栏目助手、头像、贴纸 | `mascot.png` |
| 1 | 资产清单 | 来源、Prompt、用途和版本 | `visual-assets.json` |

最小资产包为7张图；没有角色需求时可省略 `mascot.png`。

## 6. 风格路由速查

```text
要看懂 → 1 极简线条 / 4 小豆人
要形成学习进度 → 9 复古像素
要表现文化与战略 → 8 水墨写意
要讲人物与情绪 → 10 情绪速写 / 17 墨线绘本
要建立现代项目识别 → 11 二维水彩 / 18 暖色扁平
要制作活动或编辑主视觉 → 13 北欧纸雕 / 16 聚光水粉
要建立角色IP → 15 大鼻软偶
要连续家庭或团队故事 → 3.1 潦草蜡笔合同
要制造反差和传播感 → 2 蜡笔童涂 / 5 MS Paint
```

每个项目建议：一个主视觉风格 + 一个功能讲解风格。除非有明确叙事理由，不要在同一项目内随意混用多个主视觉。

## 7. 五步操作流程

### Step 1 · 写清交付目的

不要先说“我要一张水彩图”，先说明：

- 给谁看；
- 放在哪里；
- 用户看完要理解、记住、感受还是行动；
- 图片是否需要进入连续系列。

### Step 2 · 确定图片职责

从以下角色中选一个：

- 封面；
- 讲解；
- 场景流程；
- 情绪故事；
- 分享卡；
- 角色IP。

一张图只承担一个主要职责。

### Step 3 · 路由风格并提交内容

只提交：

- 风格编号；
- 主体、动作、关系和必要道具；
- 准确标题或不加文字；
- 画幅比例；
- 可选角色参考。

不要在主体字段追加第二套线条、五官、色板、材质或纸面规则。

### Step 4 · 生成和验收

检查：

- 内容是否准确；
- 风格身份是否命中；
- 画幅和留白是否适合落位；
- 是否出现错误文字或伪中文；
- 连续角色和色板是否漂移；
- 3.1 是否完整执行锚点与三阶段合同。

### Step 5 · 归档和复用

保留：

- 最终图片；
- 完整 Prompt 或 JSON；
- 风格编号和上游 commit；
- 图片职责与对应章节；
- 生成时间、模型和版本；
- 失败样例与修正原因；
- alt 文本和推荐落位。

## 8. 可复制请求模板

```text
请使用本项目固定的 hand-drawn-styles 上游配方，为以下交付生成视觉资产。

【交付场景】项目介绍 / PPT / 报告文章 / 教程 / 社媒 / 产品网站 / 品牌活动
【目标受众】……
【图片职责】封面 / 讲解 / 三幕流程 / 情绪故事 / 分享卡 / 角色IP
【用户看完要】理解 / 记住 / 感受 / 行动
【核心内容】……
【使用位置】……
【画幅比例】……
【是否连续系列】是 / 否
【准确文字】…… / 不加任何文字

执行要求：
1. 先根据传播任务推荐1个主风格和1个备选风格，并说明理由。
2. 从 upstream/STYLES.md 原样提取最终选中风格的完整配方，不得缩写、同义改写或混配。
3. 只把内容、准确文字和比例填入上游占位符，不得追加第二套风格规则。
4. 如果是连续系列，先建立角色/画风锚点，再逐张携带锚点生成。
5. 如果使用3.1，必须输出正式JSON并完整执行三阶段workflow。
6. 图片不承担事实证明；准确数字、图表、技术结构和长文字留给原生排版。
7. 输出最终Prompt/调用合同、图片用途、alt文本和建议文件名。
```

## 9. 验收清单

- [ ] 图片职责单一明确；
- [ ] 与对应章节或幻灯片有直接语义关系；
- [ ] 没有用生成插图代替原始证据；
- [ ] 风格配方来自固定上游版本；
- [ ] 连续系列使用了角色/风格锚点；
- [ ] 图片内文字准确，或已改为后期排字；
- [ ] 有合适留白供标题和版式使用；
- [ ] 文件名、alt、Prompt、来源和版本已归档；
- [ ] 失败样例和修正理由没有被删除；
- [ ] 图片尺寸和体积适合最终载体。

## 10. 资产清单示例

```json
{
  "file": "cover.png",
  "purpose": "项目封面",
  "related_section": "项目概览",
  "style_id": "18",
  "upstream_commit": "9f150d9f4c90f3a4ace78a751d2d8263d818220c",
  "generated_by": "ChatGPT ImageGen",
  "prompt_file": "PROMPTS.md#project-coverpng",
  "alt": "研究者把散乱提示卡整理成可复用视觉档案",
  "evidence": false
}
```

`evidence: false` 用于提醒：生成插图是表达资产，不是事实证据。
