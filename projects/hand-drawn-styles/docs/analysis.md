# Hand-drawn Styles：从提示词合集到可执行视觉合同

研究基线：[`9f150d9`](https://github.com/threerocks/hand-drawn-styles/commit/9f150d9f4c90f3a4ace78a751d2d8263d818220c)，2026-08-18 固定。

## 1. 能力分层

| 层 | 上游文件 | 作用 | 是否直接生图 |
| --- | --- | --- | --- |
| Agent 适配 | `SKILL.md`、`AGENTS.md` | 让 Claude Code、Codex、Cursor 等宿主知道何时触发 | 否 |
| 执行协议 | `PROTOCOL.md` | 选风格、填变量、处理比例、决定输出格式 | 否 |
| 风格知识 | `STYLES.md` | 保存 18 个整数风格和 3.1 稳定变体的完整配方 | 否 |
| 确定性组装 | `scripts/render_prompt.py` | 原样提取配方、替换占位符、校验输入并构建 JSON 合同 | 否 |
| 图像执行 | GPT Image、Midjourney 等外部服务 | 理解 Prompt、参考图和编辑步骤，真正产生像素 | 是，且不在仓库内 |

因此，该项目应被归类为“图像生成前的视觉 Prompt 编排层”。

## 2. 已有能力

### 2.1 风格覆盖

当前版本有 19 套可调用配方：1–18 加稳定变体 3.1。它们不是同一滤镜的颜色变体，而是分别保留结构、材质和构图纪律，包括：

- 讲解类：极简线条漫画、小豆人信息图；
- 故意不精致：儿童蜡笔、MS Paint 烂涂鸦；
- 手绘与叙事：圆珠笔单线、真蜡笔、水墨、淡彩速写；
- 概念与绘本：二维水彩、暖光童画、北欧纸雕、水粉、墨线、暖色扁平；
- 非传统手绘：复古像素和大鼻软偶。

### 2.2 内容参数化

配方把会变化的内容抽为 `【主体】`、`【文字】`、`【N】`、`【分镜列表】` 等占位符。Agent 推断内容，脚本负责忠实替换，从而把“理解需求”与“保持配方原样”分开。

### 2.3 普通文本 Prompt 与正式调用合同

普通风格默认输出完整 Prompt。3.1 则默认输出 `family-crayon-card-v3` JSON，除了 Prompt 还包含：

- 每张必须携带的 `style-only` 锚点；
- 可选的连续角色参考图；
- 基础生成、第一轮涂抹修正、第二轮混乱度修正；
- 每个阶段的输入来源、保留项和中间/最终状态。

这意味着3.1已经不是单条提示词，而是一个可机读的生成工作流。

## 3. 核心原理

### 3.1 把审美感觉拆成可执行特征

配方通常同时规定正向身份和负向门禁：

- 画什么：主体、动作、道具；
- 怎么构图：留白、位置、多格结构；
- 怎么画：线宽、抖动、闭合、笔触方向、覆盖方式；
- 用什么颜色：限定色板、唯一强调色、禁止色；
- 绝不能出现什么：厚描边、统一纹理、写实体积、错误脸型等。

这比单独写一个风格名更能约束模型，但仍然依赖下游模型对自然语言的理解。

### 3.2 单一真源避免 Prompt 漂移

`STYLES.md` 是文字配方真源。协议要求 Agent 不得缩写、改写或混配；有脚本时必须从文件原样提取。我们的场景扩展也遵循这一边界：只决定风格编号和内容参数，不复制视觉规则。

### 3.3 视觉锚点补足语言表达能力

3.1 将 `assets/style-3.1/anchor-family.png` 定义为主视觉真源。参考图约束线条、五官、比例和蜡笔轨迹，Prompt 负责把这种视觉语言迁移到新人物和新场景。

锚点使用解码后的像素 SHA-256 固定身份：元数据可变化，像素不能变化。渲染器自己解析 PNG 块、CRC、过滤器和像素数据，在损坏、尺寸或像素不符时停止正式生产。

### 3.4 用分阶段编辑拆解生成难题

上游实验发现，模型容易把儿童蜡笔理解成规则的斜线纹理。单次强编辑虽然能增加混乱度，却可能改变人物和配色。因此3.1把目标拆成：

1. 基础图：先保证人物、动作和构图；
2. 温和修正：只打散大部分蜡笔排线；
3. 严格修正：只处理残余规则纹理，第三阶段才是 final。

这是一种通用经验：当一个提示同时包含“内容准确”和“局部材质极不规则”时，将内容生成和局部风格修正拆开往往更可控。

### 3.5 Fail-closed，而不是静默降级

渲染器对缺失变量、未知变量、错误锚点、受控字段中的风格注入、3.1自由文字和仅文本正式输出都直接报错。它的目标不是“尽量给个结果”，而是防止一个看似成功但已经偏离合同的调用进入生产。

## 4. 工程实现

`render_prompt.py` 的关键路径很短：

```text
canonical_style_id
  → extract_template(STYLES.md)
  → parse_vars
  → render / placeholder validation
  → 3.1 subject, title and anchor validation
  → build_payload
  → text or JSON
```

脚本使用 Python 标准库，没有图像生成 SDK。自动测试覆盖文本组装、别名、占位符、比例、锚点元数据/像素变化、角色参考顺序、风格注入和三阶段状态。

### 4.1 Windows 回归测试缺陷

固定版本的上游测试在本研究环境执行为 `18/19`。唯一失败的用例使用字符串 `assets/style-3.1/anchor-family.png` 判断 JSON 中的绝对路径；Windows 返回反斜杠，因此断言失败。渲染器已经成功构建引用，失败发生在路径文本比较而不是功能路径。我们保留上游原状，并在本项目验证中改用文件与 JSON 合同语义检查。

### 4.2 1号配方的占位符语法冲突

1号模板包含段落标签 `【最重要·硬性负向约束】`，而渲染器把所有 `【...】` 都当成占位符。于是文档所述的 `N` 与 `分镜列表` 并不是CLI渲染所需的全部变量，按正常调用会报“缺少占位符”。现有测试只断言1号模板含有 `xkcd 风格`，没有实际执行这一配方，因此没有发现冲突。这说明“配方可读取”与“配方可完整渲染”需要逐风格契约测试，不能互相替代。

## 5. 对我们的意义

### 5.1 研究内容可以获得稳定视觉表达

我们的主仓库已经积累项目研究、能力拆解、技术审计和在线展示。上游配方可以为这些内容增加一层统一而低成本的视觉表达：

- README 或展厅封面；
- 原理流程讲解图；
- 研究结论摘要卡；
- 里程碑或人物故事插画；
- 社媒传播图和阶段复盘卡。

### 5.2 可把风格选择变成场景路由

我们的扩展不再要求使用者记住19个编号，而是先选择日常目的。场景路由只返回：

```json
{
  "style": "4",
  "purpose": "研究结论信息图",
  "content": "解释为什么 Prompt 需要单一真源",
  "aspect": "3:4",
  "output": "prompt"
}
```

风格细节仍由上游维护。这样可以在不 fork 配方的情况下不断增加我们的日常场景。

### 5.3 它提供了一种可复用的 Skill 产品化方法

对我们更长期的意义不是某个蜡笔风，而是以下设计模式：

- 将经验库与执行协议分离；
- 将 Agent 推断与确定性渲染分离；
- 为高风险变体建立参考资产和完整性校验；
- 把失败样例转化成门禁与回归测试；
- 用正式调用合同描述多阶段生成；
- 业务扩展只提供参数，不维护第二套核心规则。

这些方法可以迁移到报告模板、演示文稿、视频风格、数据可视化和其他生成式内容工作流。

## 6. 局限与风险

1. 普通风格仍主要依赖文字 Prompt，没有3.1那样的视觉锚点和多阶段合同。
2. Agent 的风格识别和占位符推断不是确定性的；渲染器只保证组装过程确定。
3. 不同图像模型对长 Prompt、中文文字、参考图和编辑的支持不同，跨工具只能保证输入协议可移植，不能保证输出相同。
4. 上游基准主要是少量样图和作者人工判断，没有盲测、多人评分或稳定的自动视觉指标。
5. 图片生成的时间和成本在仓库之外，3.1正式流程至少包含一次生成和两次编辑。
6. 风格编号近期发生过迁移，研究和生产必须固定 commit。

## 7. 我们的扩展边界

为了避免把项目重新变成散乱 Prompt 集，我们遵循三条规则：

1. 不复制 `STYLES.md` 的完整风格段落到我们的场景配置。
2. 场景路由只能提交编号、内容、文字、比例和参考角色。
3. 需要改变线条、色板或材质时，应在上游配方研究中验证，而不是在业务 Prompt 后追加一段覆盖规则。

## 8. 从能力样图到内容资产

风格库里的示例图是能力证据，只说明某种视觉语言可以被复现；它们不自动代表我们的研究内容。为了验证实际使用，本项目直接用 ChatGPT ImageGen 生成三类资产：

1. **项目封面**：研究者将散乱提示卡整理成有序档案，并连接到完成插画，表达“从 Prompt 到视觉合同”。
2. **原理讲解图**：四格动作表达收集内容、选择风格、组合约束和最终出图；图片不承担准确文字，术语由 HTML 提供。
3. **里程碑故事图**：团队把失败图片重新固定到证据墙并记录原因，表达“失败样例也是回归证据”。

每张内容资产都绑定 `purpose`、对应章节、页面位置、复用场景、alt 与生成 Prompt。这样图片才可以被审计和复用，而不是成为与正文无关的装饰。

生成文件、用途和完整提示词见 [`showcase/assets/generated/`](../showcase/assets/generated/)。
