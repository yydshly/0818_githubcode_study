> 固定版本：`499eb43b4ecb35ba0653c6d51d18a950efef160a`

## 1. 数据在 Luopan 中的作用

Luopan 的完整工作链不是“抓取资料后生成报告”，而是：

```text
识别研究对象
→ 确认用户决策目标
→ 确定必要信息清单
→ 按市场与证据等级获取信息
→ 统一实体、时间、币种与统计口径
→ 区分事实、计算、推断和建议
→ 运行行业 / 投资 / 求职判断框架
→ 对抗验证并输出条件性结论
```

信息获取是判断底盘，但不是最终目的。只有与当前决策问题有关、来源可追溯、口径能够解释的信息才进入事实底座。

## 2. 证据分级

| 等级 | 定义 | 典型来源 | 使用边界 |
| --- | --- | --- | --- |
| A 级 | 原始证据 | 监管申报、交易所公告、公司年报、招股书、政府/法院记录 | 可直接支撑核心事实，仍需检查时间、主体和口径 |
| B 级 | 可核验二手证据 | westock-data、行业报告、权威媒体、评级机构和数据库 | 用于结构化快扫和补充语境；关键数字尽量回核 A 级 |
| C 级 | 调查线索 | 员工评价、社交网络、论坛、自媒体、无明确口径的数字 | 只能指出继续调查方向，不能独立支撑核心结论 |

每条核心结论还必须包含支持证据、最强反证、推理链、置信度、信息局限和可能推翻结论的条件。

## 3. 结构化金融数据：westock-data

Luopan 的公司研究要求首先使用外部 CLI `westock-data` 进行数据快扫。其数据来自腾讯自选股接口，与腾讯微证券、腾讯自选股应用同源。

| 命令 | 获取内容 | 用途 |
| --- | --- | --- |
| `westock-data profile <code>` | 公司概述、行业分类、上市日期 | 实体消歧与身份确认 |
| `westock-data finance <code> --num 4` | 利润表、资产负债表、现金流量表 | 多期财务与现金流分析 |
| `westock-data consensus <code>` | 收入、利润、EPS 预测和估值区间 | 前瞻预期与估值输入 |
| `westock-data kline <code> --period month --limit 12` | 历史价格 | 价格背景与基准日 |
| `westock-data search <industry> --type sector` | 行业板块代码 | 行业板块识别 |
| `westock-data sector constituent <pt_code>` | 板块成分股 | 行业公司清单 |
| `westock-data sector valuation <pt_code>` | PE/PB/PS 与历史百分位 | 板块估值 |
| `westock-data sector finance <pt_code>` | 板块财务聚合 | 行业整体经营情况 |

### 能力边界

- `westock-data` 不包含在 Luopan 仓库中，也没有随仓库提供安装脚本、版本约束或可用性检测。
- 在 Luopan 自己的证据标准中，它属于 B 级聚合数据，不是公司原始申报。
- A 股关键数字应回到巨潮资讯或交易所，港股回到 HKEXnews，美股回到 SEC 文件。
- 如果命令不可用或数据缺失，应转入原始文件路线并降低自动化程度，不能补造字段。

## 4. 上市公司原始数据路线

### 4.1 A 股

优先顺序：

1. 巨潮资讯；
2. 上海证券交易所；
3. 深圳证券交易所；
4. 北京证券交易所；
5. 公司投资者关系网站。

主要获取：

- 年报、季报、招股书；
- 问询回复、重大事项公告；
- 合并报表与业务分部；
- 扣非利润、非经常性损益；
- 政府补助、关联交易、股权变化。

### 4.2 港股

优先顺序：

1. HKEXnews；
2. 公司投资者关系网站；
3. 发行人的年报、中报、公告、通函和招股书。

处理规则：

- 有官方中文版本时优先引用中文版本，并用英文版本核对歧义；
- 保留 PDF 页码、表格标题和披露日期；
- 多地上市时明确本次证券标的、价格和估值币种；
- 不使用中文财经摘要替代正式披露。

### 4.3 美股与 SEC 申报主体

| 数据源 | 作用 |
| --- | --- |
| SEC company tickers | ticker/公司名映射到 CIK |
| SEC submissions | 申报历史和原始 filing 地址 |
| SEC companyfacts | 标准 XBRL 财务事实 |
| SEC Archives | 10-K、10-Q、20-F、6-K 等原始文件 |

仓库自带 `modes/company/scripts/sec_fetch.py`，可以提取少量标准 US-GAAP/IFRS 概念：

- 营收；
- 净利润；
- 经营现金流；
- 现金；
- 资产；
- 权益；
- 稀释股数。

脚本会保留 CIK、accession、form、filed、period、unit、taxonomy、tag 和原始申报链接。

限制：

- 只识别少量标准标签，主动忽略公司自定义标签；
- 当前脚本支持的表单为 `10-K`、`10-Q`、`20-F`、`6-K`；
- fixture 单元测试不能替代真实网络、复杂财年、重述和多单位验证；
- 自动事实是候选输入，业务分部和会计口径必须回到原始 filing。

### 4.4 其他上市市场

优先使用当地监管机构、交易所和公司正式披露。在没有建立稳定数据路由前，使用网页/PDF 研究并降低自动化程度，不能把 SEC 规则直接套到其他市场。

## 5. 非上市公司信息路线

按以下顺序建立证据拼图：

1. 政府、工商、法院、处罚、发债和招股材料；
2. 公司官网、产品文档、官方招聘、官方融资公告；
3. 投资机构、客户、供应商、政府采购和可核验媒体；
4. 有权限时使用商业数据库；
5. 员工评价、论坛和社交内容只作为线索。

允许使用但必须标注局限的代理信号：

- 融资时间和金额；
- 产品活跃度；
- 用户、客户、门店和订单；
- 招聘岗位与组织结构；
- 管理层变化；
- 诉讼、处罚和采购记录。

禁止从代理信号反推出看似精确的营收、利润、增速或估值。

## 6. 行业研究信息路线

行业模式先识别行业类型，再从六个视角中至少覆盖四个。

| 视角 | 优先来源 | 搜索目标 |
| --- | --- | --- |
| 政策/监管 | 政府官网、发改委、工信部、行业主管部门 | 政策约束、牌照和规划 |
| 资本/IPO | 证监会、交易所、招股书、融资公告、券商投行材料 | 融资、上市与资本流向 |
| 产业链 | 公司财报、行业协会、券商和咨询机构深度报告 | 商业模式、利润池和代表公司 |
| 技术趋势 | 论文、专利、技术白皮书、公司技术文档 | 技术壁垒与替代风险 |
| 需求/消费 | 咨询机构、用户调查、市场研究 | 市场需求、用户结构和增长 |
| 人才/岗位 | 公司招聘官网、BOSS 直聘、猎聘、牛客等 | 岗位分布、人才供需与业务信号 |

行业类型会改变信息权重：

- 消费/内容型：需求端、流量端和人才端优先；
- 科技/制造型：产业链、技术和资本优先；
- 平台/交易型：政策、交易规模、需求和平台规则优先；
- 服务/人力型：人才、人效和客户需求优先；
- 政策/监管型：监管、牌照与资产规模优先。

### 获取流程

```text
市场规模 / 产业链 / 商业模式 / 关键公司 / 最新动态热身搜索
→ 写 Day-1 假设
→ 建立公司清单并按权力而非产业位置分层
→ 获取 2–6 份最有价值的完整材料
→ 比较 2–3 个不同机构或视角的框架
→ 补齐缺失视角
→ 对抗验证和质量门禁
```

不能获得可比份额时，不计算 CR8；不能获得环节利润率时，不拼接伪精确利润池。

## 7. 行情、估值与外部变量

需要绑定日期和来源的变量包括：

- 当前股价和市值；
- 总股本和预期稀释；
- 汇率；
- 无风险利率；
- 分析师一致预期；
- 历史估值和同行估值；
- 用户目标回报率或通用机会成本。

行情数据可以通过 `westock-data kline` 和 `consensus` 获取，也可以替换为其他可靠来源。没有可靠价格、股数或正常化现金流时，价格门必须输出 `INSUFFICIENT`，不能降级成模糊的“合理”。

## 8. 单条事实的归档字段

深度报告中的每条关键事实至少记录：

| 字段 | 含义 |
| --- | --- |
| `id` | 唯一事实 ID |
| `field` / `value` | 指标和值 |
| `period` | 财年、季度或日期 |
| `currency` / `unit` | 币种和单位 |
| `scope` | 合并、分部、地区或证券标的 |
| `source_ids` | 对应来源 ID |
| `confidence` | 高、中、低及降级原因 |
| `is_calculated` | 是否为计算值；计算值必须保存公式和输入 |
| `is_inference` | 是否为推断，不能伪装成原始事实 |
| `conflicts` | 已知的口径冲突或反方证据 |

数据健康度按维度记录为：完整、部分完整、缺失、存在冲突、已过期或不适用。不得用一个综合分数掩盖关键数据缺失。

## 9. 冲突与失败处理

- 来源冲突：展示双方，检查时间、币种、准则、调整口径和母子公司边界；
- 搜索结果不足：提示行业名或范围可能不准确；
- 数据过旧：明确标注年份，不把旧数据写成当前状态；
- 非上市公司财务缺失：转向可归因代理信号，不补造精确数据；
- 市场价格缺失：请求价格快照，或只做公司质量判断；
- 外部 CLI 不可用：转入原始披露路线并记录依赖缺失；
- 核心冲突未解决：降低置信度，必要时输出“证据不足”。

## 11. 面向本研究主仓库的复用原则

研究其他 GitHub 项目时沿用同一思路：

```text
上游源码、commit、测试、许可证               → A 级
上游 README、官方文档、release、issue         → B 级
第三方文章、社区评论和社交内容                 → C 级
```

每个项目都应保存：来源、获取时间、固定版本、验证命令、实际产物、失败条件和可能推翻结论的新证据。这样“信息获取”才会变成可复现研究，而不是一次性搜索记录。
