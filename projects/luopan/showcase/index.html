02 / PRINCIPLE

它的原理不是“一个更懂商业的模型”，而是一套约束研究行为的路由和门禁。

模型负责理解与推理；Skill 规定何时问问题、去哪里找证据、按什么顺序判断、什么情况下必须承认证据不足。

路由原理

先识别对象，再确认目的，最后加载完整方法。

01对象识别
行业、赛道、产业链 → 行业模式；具体公司、股票、岗位、Offer → 公司模式。
02用途确认
公司研究若没有目的，只问一次：投资、求职或两者并重；选择前暂停搜索。
03方法加载
行业读取九阶段方法；公司按市场和受众加载数据、投资或求职框架。
04同源交付
公司报告先形成 JSON 真源，再生成 HTML 和 Markdown，避免数字与结论漂移。

结论契约

每个判断都必须交代“为什么信、哪里可能错、什么会推翻”。

  • 判断状态通过、需关注、不通过、证据不足或不适用；PASS 只代表继续研究门槛，不等于买入或入职。
  • 支持证据事实保留时间、币种、口径、来源、页码，以及是否为计算或推断。
  • 最强反证主动找能破坏当前叙事的材料，不把管理层或媒体叙述直接当事实。
  • 推理链把事实、计算、推断和建议分开，结论强度不能高于证据强度。
  • 推翻条件说明哪个变量、事件或新证据出现后，需要改变当前判断。
03 / DATA LINEAGE

数据不是“来自网络”，而是按市场和证据等级进入事实底座。

Luopan 将原始披露、结构化金融平台、行业研究和线索分层使用。来源等级越低，越不能独立支撑核心结论。

A

原始证据

决定核心数字与公司身份。

  • SEC 10-K / 10-Q / 20-F / 6-K
  • 巨潮、上交所、深交所
  • HKEXnews 与公司年报
  • 政府、法院、正式公告
B

可核验二手数据

提高速度并补充行业语境。

  • westock-data / 腾讯自选股聚合
  • 有方法和日期的行业报告
  • 权威媒体、评级和数据库
  • 关键数字仍回核 A 级
C

调查线索

只能告诉研究者“去哪里继续查”。

  • 员工评价与社交内容
  • 论坛、自媒体与未说明口径数字
  • 多源一致前不支撑强结论
  • 必须标注未经官方证实
6×

行业多视角

行业研究至少覆盖其中四个。

  • 政策 / 监管
  • 资本 / IPO
  • 产业链 / 技术
  • 需求 / 人才
关键能力边界

westock-data 是 Luopan 方法要求优先调用的外部 CLI，数据被其方法定义为 B 级；但这个命令、安装方式和版本并不在仓库内。仓库自带的自动抓取器只有 SEC 最小实现。因此“方法支持的数据路线”不等于“仓库开箱即有的数据能力”。

04 / DECISION ENGINES

三套判断引擎解决三种不同问题，不能混成一个总分。

切换查看行业权力、投资交易条件和求职职业资本如何分别形成决策。

行业：九阶段研究＋权力评分

8 项权力指标 + R&D 加分 → 0–10

目标不是列产业链，而是判断谁拥有定价权、现金流和不可替代性。先识别行业类型和视角权重，再建立 Day-1 假设，最后用事实推翻或修正。

类型与用户视角热身搜索Day-1 假设公司与权力分层多报告补缺骨架与双格式对抗验证
权力指标

毛利率及弹性、应收应付、预收预付、客户与供应商集中、转换成本、经营现金流/净利润，并以研发强度加分。

竞争五步

定义边界 → 集中度 → 利润池 → 进入壁垒 → 生命周期；数据不足时定性，不硬算 CR8。

审计发现

原文“应付低＝占供应商钱、应收高＝回款快”疑似方向写反，实际应用前必须修正，不能照表机械评分。

投资：七道门，最后才判断价格

安全边际 = (基准价值 − 当前价格) / 基准价值

先判断是否理解公司和财务是否可信，再判断商业模式、护城河、管理层与风险；公司质量通过后，当前交易条件仍可能失败。

业务可理解性商业模式护城河管理层与文化财务质量风险与反证价格与机会成本
三情景估值

悲观、基准、乐观分别写现金流、利润率、再投资、折现率、终值、债务和稀释；高敏感时输出区间。

反向估值

从当前市值倒推市场押注的增长、利润率和终值，检查是否需要长期接近乐观情景。

价格门

高/中/低可预测性参考 15–20%、25–30%、35–50%+ 安全边际；这是执行校准，不是市场定律。

求职：五层漏斗，结论随信息层级升级

职业资本净收益 = 获得 − 时间 − 风险 − 最佳机会

公司名只能得到公司级初筛；加入业务线后升级为业务级判断；只有岗位、职级、薪酬、上级、团队和个人目标齐全，才可能形成 Offer 级建议。

公司会不会沉业务是不是核心舱岗位能积累什么上级与组织是否可靠是否适合这个人
岗位价值

能力密度、成果所有权、资源杠杆、可迁移性和两三年后的选择权增量。

风险分级

一票否决、强制核实、普通代价分开；不是看到任一红灯就机械跳过。

面试验证

输出 10 个低防御问题，向 HR、经理和未来同事交叉验证；绿黄红只用于用户后台复盘。

05 / APPLIED STUDY

把 Luopan 用到我们的背景：AI 编程 Agent 行业实战。

这不是再解释 Luopan，而是用它的行业方法研究我们正在使用的工具生态，并据此决定当前主项目应该建设什么。

85%JetBrains 2025 调查中，经常使用 AI 开发工具的开发者比例
但 Stack Overflow 同年显示 52% 不使用 Agent 或只用简单 AI 工具。

核心修正

模型能力重要，但仓库入口、执行环境、验证闭环和企业治理共同决定行业权力。

结论不是“再造一个 Agent”。我们应直接采用成熟 Agent 作为执行引擎，改造 Luopan 的证据与决策方法，建设跨 GitHub 项目的研究、复现、扩展和展示控制层。

采用

使用 Codex 等成熟 Agent 完成源码读取、修改、测试和浏览器验证。

改造

迁移 Luopan 的路由、信源分级、对抗验证和 JSON 单一事实源。

不做

衡量

用“仓库链接到可复现理解和可展示扩展的时间”，而不是生成代码行数。

06 / EXTENSION

在行业与公司之外，新增“GitHub 项目研究”路由。

保留 Luopan 的研究纪律，替换它的商业研究对象，形成当前主仓库可重复使用的收录闭环。

LUOPAN → CODE STUDY

从仓库链接到可复现、可解释、可扩展、可展示。

这个扩展不评价“项目火不火”，而是回答能力是否真实、原理在哪里、依赖和许可证是什么、与当前项目如何连接，以及扩展是否经过验证。

扩展 Skill研究 JSON仓库扫描
  1. 固定研究对象记录 upstream URL、commit、license 和研究日期。
  2. 确定性扫描识别语言、manifest、测试、CI、文档、许可证和 Skill。
  3. 能力分层把能力分为已验证、官方宣称、外部依赖和实现缺口。
  4. 原理追踪按输入、路由、核心转换、验证、产物五层追踪源码。
  5. 关联扩展从主项目真实工作流出发，定义一个可验收的扩展闭环。
  6. 统一展示JSON 真源同步生成研究文档、交互页面和主索引入口。
